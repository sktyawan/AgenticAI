# ADR-005: Pemisahan audit-signer dan vault dari runtime agent

- Status: **proposed** (yang mengesahkan: Seti)
- Tanggal: 2026-10-29
- Terkait: docs/STRUCTURE.md §2, §4

## Konteks dan pernyataan masalah

Audit hanya bisa dipercaya bila pihak yang diaudit tidak bisa
mengubah jejaknya sendiri. Bila runtime agent memegang kunci
penandatangan audit atau secret jangka panjang, satu agent yang
disusupi bisa menulis ulang sejarah — dan tidak ada yang bisa
membuktikan.

## Opsi yang dipertimbangkan

1. **Service terpisah: `audit-signer/` dan `vault/`** — audit-signer
   satu-satunya pemegang kunci penandatangan rantai hash; vault
   satu-satunya pemegang secret; runtime agent tidak pernah memegang
   keduanya. Agent meminta tanda tangan dan secret lewat API dengan
   principal yang jelas, dan setiap permintaan tercatat.
2. Kunci di runtime agent dengan enkripsi lokal — lebih cepat, tetapi
   agent yang disusupi memegang kunci yang melindunginya sendiri.
3. Kunci di tool gateway — lebih baik dari opsi 2, tetapi gateway
   menjadi satu titik yang memegang terlalu banyak wewenang.

## Keputusan

**Opsi 1 yang diusulkan: pemisahan penuh.** Keputusan ini masih
usulan sampai disahkan Seti, tetapi prinsipnya sudah menjadi fondasi
struktur repo (§2, §4).

## Konsekuensi

- Positif: audit append-only yang benar-benar independen; secret
  tidak tersebar di semua service; jangkar eksternal membuat
  pemalsuan terdeteksi.
- Negatif: satu hop jaringan tambahan untuk tanda tangan dan secret;
  audit-signer dan vault menjadi komponen kritis yang wajib tersedia.
- Mitigasi: audit-signer dan vault masuk direktori sensitif
  (2 reviewer, ruleset); ketersediaan dijaga lewat desain service
  yang sederhana dan terisolasi.

## Batas otonomi, eval penggerbang, dan fallback

- Batas: agent tidak pernah meminta kunci penandatangan, mengakses
  vault di luar izinnya, atau menulis audit_events secara langsung.
- Eval penggerbang: agent yang disimulasikan tersusupi tidak boleh
  bisa memalsukan atau menghapus entri audit.
- Fallback: tidak ada fallback yang melemahkan pemisahan ini; bila
  audit-signer tidak tersedia, sistem gagal tertutup (menolak aksi),
  bukan berjalan tanpa audit.
